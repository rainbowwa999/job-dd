# 岗位分析
1. 岗位实质：服务谁、解决什么、交付什么、对什么结果负责；职位名和实际职责是否一致。
2. 能力拆解：JD 原文 → 实际任务 → 能力；区分硬门槛、核心项与加分项。
3. 个人匹配度：直接做过、可迁移、暂无证据。分别判断面试匹配与长期适合度。
4. **KPI 与责任边界**：直接列出预测的考核指标、结果责任及主要依赖。表格可用「预测 KPI｜衡量什么｜可能的责任边界」。表格下统一注明「以上根据岗位描述与业务场景预测，并非公司已确认的考核规则」。不在本节写建议或追问。
5. **工作内容与时间占比**：自动检索同类岗位的公开 JD，优先比较同业务场景、同职级的职责，与目标 JD 一起推断常态工作分配。用「工作内容｜预测时间占比｜判断依据」表格列出，采用合计 100% 的粗略估计；附同类 JD 来源，说明占比为预测、不是实测工时。同类岗位未找到时仍根据当前职责给出低置信度估计，不编造来源。不在本节写追问。
6. **工作强度**：独立成节，描述预测的日常节奏、高峰期、晚间或周末加班、值班与临时响应等情况，并说明信号来自哪里。评估岗位本身，不代入个人上一份工作的作息或经历。不在本节写追问。
7. **疑点**：用「疑点｜可疑原因｜建议追问」三列表格。把 KPI、权限、工作量、加班、团队、薪资和用工主体等需要向招聘方核实的问题集中在此。本节不放投递判断。
8. **公司背调**：独立成节。用公司全称、品牌、城市交叉检索工商、官网、招聘页、媒体与公开求职反馈。区分集团、团队、招聘标注人数与参保人数；注明来源及日期。匿名帖作为线索，检查是否独立及是否指向同一团队。主体不明时先分析 JD，标注背调待确认；未查到写「本次公开检索未发现」。不要在背调后附追问或投递建议。

完整岗位分析按 1–8 分节呈现，不合并章节。区分事实、预测和待核实事项。单独交付岗位分析时，在八节之后另起一段给出「建议投递」或「不建议投递」，用一句话概括匹配证据与决定性风险。关键事实不足时给条件式判断；没有简历时注明无法判断个人匹配度。不要在此展开简历取舍、项目推荐或直接写招呼语。交付岗位分析后，在结尾列出本岗位尚可继续的模块，并结合当前 JD 简要说明每项能做什么。主流程选项包括简历修改建议或定制简历、招聘招呼语、面试准备。已交付或明确跳过的模块不再列出。请用户选择接下来要做的项目，用户已明确要求连续完成的模块则直接按其范围交付。
