# job-dd

**看到一个岗位，想知道值不值得投？把 JD 发过来就行。**

job-dd 的 DD 是 Due Diligence（尽职调查）。它先帮你看清实际职责、可能的考核方式和公司背景。如果你想争取这个机会，可以接着改简历、写招呼语。约到面试后，再练面试题和自我介绍。

## 从一句话开始

> 帮我看看这份新媒体运营 JD：实际是做内容，还是要背获客指标？

直接发 **JD 原文、截图或链接**。如果你只想要一个结果，也可以直接说：

- **只改简历**：按这个岗位改写工作经历和重点项目。
- **只写招呼语**：把我最匹配的两项能力写清楚，每条带一个真实案例。
- **准备业务面**：告诉我最该练哪些题、该用哪个项目来答。
- **写自我介绍**：给我一版约一分钟、面试时能直接说的稿子。

同一个岗位可以分几次做。比如 HR 后来补充了周末轮值，直接发这条新消息，助手会更新相关判断。

## 看一个例子

假设你想投小游戏活动运营岗。JD 要求做用户分层、活动规则和后台配置；你做过回流活动，但没独立搭过通用后台。

助手会把「按回流人群设计任务、推动活动上线」放进简历重点。写招呼语时，用同一个真实案例说明匹配度；准备业务面时，再把「怎样将任务规则做成可复用配置」作为场景题练习。

## 怎么试用

下载或克隆仓库后，按工具说明导入包含 `SKILL.md` 的整个 `job-dd/` 目录。在 Codex 里也可以打开仓库根目录，直接说：

> 请读取当前目录的 `SKILL.md`，帮我分析这份 JD。[粘贴 JD 或附截图]

**简历可以稍后再发。** 有多个版本可以一起提供，也可以用文字补充简历外的项目。助手会整理成一份 Markdown 母版并告知保存位置。暂不提供简历，也能分析岗位、查公司和准备通用面试题；个人匹配和个性化文案会注明缺少材料。

## 适合哪些岗位？

适合常见的**运营、产品、市场、商务和职能岗位**，包括新媒体、品牌市场、用户增长、平台产品和客户成功。实习、工作、个人项目或作品都可以作为证据。

<details>
<summary>检索、文件与隐私</summary>

公司背调和同类岗位对照会检索公开资料；面试准备会查证行业和产品信息。KPI、时间占比和强度是预测，匿名反馈是核实线索。个人职责和结果以候选人提供的材料为准。

**每个岗位默认存成一份 Markdown。** 第一次交付时会在当前工作区创建 `JobSearchPrivate/岗位档案/` 并保存结果。后续内容更新到同一份档案。每次保存或更新成功后，回复都会附上文件链接。你也可以指定其他私人目录。

**想回到旧岗位，直接说岗位名。** 例如「继续准备几米物联的平台产品经理面试」。在同一个工作区开新对话也能按岗位名续做。换了工作区，可以提供原档案路径。遇到同名岗位时会请你确认是哪一份。

只记得大概也可以说「前几天写过招呼语的那个客户成功岗，约面了，帮我准备业务面」。也可以重发 JD 截图并说「帮我准备这个岗位的面试」。两种方式都会先查已有档案，匹配后沿用之前的分析和经历材料，把面试准备更新到原档案。

如果只想在聊天里处理，说「这份岗位不存档」即可。简历母版单独保存在工作区的 `JobSearchPrivate/简历母版.md`。Skill 不会自动联系招聘方或投递。`JobSearchPrivate/` 已加入本仓库的 Git 忽略规则。手动上传文件时，也请跳过该目录。

</details>
